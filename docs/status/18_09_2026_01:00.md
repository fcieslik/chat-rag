W trakcie konfiguracji wystąpił 401, ponieważ początkowo API Gateway miał:

Authorization:
chat-rag-cognito

Authorization Scopes:
puste

a frontend wysyłał:

access_token

W REST API Gateway:

Authorization Scopes = puste

oznacza użycie ID tokena.

Po dodaniu:

Authorization Scopes:
chat-rag-api/read

API Gateway oczekuje:

access_token

i sprawdza jego scope.

To jest bardzo ważne rozróżnienie:

ID token
→ Who is the user?

Access token
→ What API access does the user have? 20. CORS + Cognito

Nie tworzyć ponownie istniejących zasobów.
Nie przywracać publicznego ALB.
Backend pozostaje za Internal ALB.
API Gateway jest publicznym entry pointem.
Cognito odpowiada za authentication / token issuance.
API Gateway odpowiada za authorization enforcement.
Na obecnym etapie każdy poprawnie uwierzytelniony użytkownik z odpowiednim scope może korzystać z /chat.
Nie używamy Cognito Groups.
Nie używamy custom roles do tego prostego przypadku.
AWS Console pozostaje głównym sposobem nauki/deploymentu.
Bez Terraform na obecnym etapie.
Przy instrukcjach AWS sprawdzać aktualną dokumentację zamiast zakładać, że UI wygląda jak dawniej.
Instrukcje mają być krótkie i krokowe.
Po CI/CD kończymy etap infrastruktury.
Następnie priorytetem jest aplikacja AI, a nie dalsze rozbudowywanie AWS.
